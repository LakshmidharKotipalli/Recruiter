Group 1 — Modules 01–04

Core Infrastructure

01
Abstract BaseLLM

BaseAgent

agents/base.py
Abstract foundation every LLM agent inherits. Provides a unified calling interface across Anthropic and OpenAI, lazy client initialization, and a robust JSON parser with balanced-bracket fallback when models return wrapped output.
Key Methods
_call_llm() _call_llm_with_tools() _parse_json_response() _init_client()
_call_llm() works with both Anthropic and OpenAI. _call_llm_with_tools() is Anthropic-only and raises ValueError otherwise. JSON parsing uses balanced-bracket extraction as a resilient fallback.
02
InfrastructureAsync

EventBus

agents/event_bus.py
Per-request async SSE streaming backbone. Wraps an asyncio.Queue with configurable backpressure (max 1000 items) to prevent unbounded memory growth. Each SSE request gets a fresh EventBus, discarded on completion.
Key Methods
emit() close() stream()
Events are formatted as data: <json>\n\n for SSE protocol compliance. The stream() async generator yields until a sentinel close signal. Created fresh per request to isolate concurrent users.
03
InfrastructurePure Python

HITLStore

agents/hitl.py
Human-in-the-Loop checkpoint system. Each checkpoint wraps an asyncio.Event for non-blocking wait/resume. The store is an in-memory singleton dict keyed by run_id, with a 300-second auto-proceed timeout.
Key Classes & Methods
HITLCheckpoint HITLStore wait() resume()
HITLCheckpoint uses asyncio.Event for blocking/unblocking coroutines. The module-level singleton is single-process only — swap to Redis for multi-instance deployments. 300s timeout auto-proceeds with defaults.
04
SchemasAnthropic

Tool Schemas

agents/tools.py
Anthropic tool_use JSON schema definitions consumed by the OrchestratorAgent's ReAct loop. Two schema sets cover sourcing and resume-matching workflows with shared and unique tools.
Sourcing Tools (5)
extract_jd generate_queries fetch_profiles score_candidates assess_quality
Resume Tools (5)
extract_jd parse_resumes score_candidates relax_requirements assess_quality
Includes strategy enums for query generation (targeted, broad, location_relaxed) and requirement relaxation (reduce_must_have, expand_nice_to_have, relax_seniority).
Group 2 — Modules 05–09

Pipeline Agents

05
LLM-Powered

JDExtractionAgent

agents/jd_extraction.py
Transforms raw job descriptions into a typed SearchSpec through a multi-step LLM pipeline. Handles vague or poorly-written JDs by scoring quality, rewriting prose, and inferring missing skills from role knowledge.
3-Step Pipeline
Step 1: JD Cleaner Step 2: Gap Filler Step 3: Extractor
Step 1 scores quality 0–10, lists issues, rewrites into clean prose. Step 2 applies role knowledge to infer missing skills. Output is a typed SearchSpec. Five mock variants: Python, Data, Frontend, ML, DevOps. Falls back to mock on any failure.
06
LLM-Powered

QueryGenerationAgent

agents/query_generation.py
Converts a SearchSpec into Boolean search queries tailored to each integration source. Generates primary and fallback queries with AND/OR syntax for maximum recall.
Key Methods
generate() _build_mock_queries() _live_generate()
Targets 3 sources: google_cse, naukri, pdl. Produces 3 primary + 2 fallback queries per source. Live mode uses a single LLM call. Mock mode constructs queries directly from SearchSpec fields.
07
Pure PythonAsync

ProfileFetchingAgent

agents/profile_fetching.py
Dispatches queries to all configured integrations in parallel using asyncio.gather. No LLM involvement — purely async orchestration with graceful per-source failure handling.
Key Methods
fetch() _fetch_source() _merge_results()
Uses asyncio.gather for parallel dispatch to Google CSE, Naukri, and PDL. Each source fails independently without crashing others. Returns (profiles[], source_availability) tuple.
08
LLM-Powered

ResumeParserAgent

agents/resume_parser.py
Extracts structured RawProfile objects from uploaded PDF and text resumes using LLM extraction. Standardizes skill names and supports batch processing for multiple uploads.
Key Methods
parse() parse_batch() _extract_structured()
Source field is set to "resume_upload". Five mock variants with realistic Indian tech professional data. Used by ResumeMatchPipeline to bypass query generation and external fetching entirely.
09
LLM-Powered

RankingAgent

agents/ranking.py
Scores and buckets candidates using a weighted formula across four dimensions. Combines deterministic scoring with LLM-generated natural language reasoning for recruiter-facing explanations.
Scoring Formula
50% must-have 25% nice-have 15% seniority 10% location
Must-have gate: missing >1 must-have skill results in auto-rejection regardless of total score. Seniority detection uses title patterns (jr/mid/sr/lead/principal). Batch LLM call generates NL reasoning. Mock mode uses score-aware templates.
Group 3 — Modules 10–12

Orchestration & Decision Logic

10
LLM-PoweredAsync

OrchestratorAgent

agents/orchestrator.py
Central pipeline driver coordinating all agents. Supports two modes (sourcing and resume matching) with a unified agentic ReAct loop. Maintains strict per-run state isolation via _RunContext.
Key Methods & Classes
_RunContext _agentic_run() _mock_run() _dispatch_tool() _assemble_output()
_RunContext dataclass isolates per-run mutable state (search spec, profiles, scores, trace). Mock mode uses a state machine (steps 0–6). HITL integration at jd_review and profile_count checkpoints. Force-accept promotion in output assembly.
11
Pure Python

QualityChecker

agents/quality_checker.py
Pure Python decision engine with no LLM dependency. Evaluates pipeline quality after each iteration and determines whether to accept results, force-accept, or refine the search strategy.
Key Methods
assess() _check_thresholds()
Decision tree:
• max_iterations reached → accept (or force_accept if 0 accepted)
• accepted ≥ min_accepted → accept
• thin pool → refine_broader
• high close:accept ratio → refine_location_relaxed
• default → refine_broader
All thresholds are env-configurable.
12
Pure Python

DeduplicationStage

agents/deduplication.py
Identity resolution engine using a 4-priority rule system to cluster duplicate profiles from different sources. Merges data, tracks provenance, and records field-level diffs.
Dedup Rules (P1–P4)
P1: Email P2: Name+Company P3: Name+Title+Location P4: Phone
Name token overlap ≥80% for fuzzy matching. Source priority: resume > PDL > Naukri > CSE. Uses O(n²) clustering. Skills are unioned across duplicates. Alt profiles preserve source URLs and field diffs.
