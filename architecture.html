System Architecture

AI Recruiter —
Two Paths, One Engine

An agentic pipeline that understands job descriptions, finds or evaluates candidates, and delivers a ranked shortlist. Two modes of operation share the same AI orchestrator, scoring formula, and human checkpoints.

How Recruiting Happens
Two Modes of Operation
The recruiter chooses how candidates enter the system. Both modes pass through the same AI intelligence, scoring, and quality-checking layers.
🌐
Sourcing Mode
Find candidates from the internet
Recruiter provides a job description. The AI searches Google, Naukri, and People Data Labs simultaneously to find matching professionals, then scores and ranks them.
1🧹Understand the job description
H1✋Recruiter reviews extracted spec
2🔍Build search queries for each source
3🌐Search all platforms in parallel
4🔗Remove cross-platform duplicates
H2✋Recruiter checks if pool is large enough
5📊Score and rank all candidates
QC🔄Quality check: refine search if too few matches
📄
Resume Match Mode
Score uploaded resumes against a job
Recruiter provides a job description AND uploads resume files. The AI reads each resume, extracts structured data, then scores everyone against the job requirements. Dedicated endpoints: POST /api/resume/match and POST /api/resume/match/stream
1🧹Understand the job description
H1✋Recruiter reviews extracted spec
2📄Parse all uploaded resumes
3📊Deduplicate, score, and rank
QC🔄Quality check: relax criteria if too few matches
🔧If relaxed: re-score with loosened must-haves

Layer 03

Query Generation Layer

Sourcing only

The Query Generation Agent creates optimized Boolean search queries tailored to each platform's syntax. Produces 3-5 primary queries per source, each with a broader fallback variant. Supports three strategies: precise (default), broader (relaxed skills/seniority), and location_relaxed (drops location filter).

Layer 04

Profile Acquisition Layer

SourcingResume

How candidates enter the system depends on the mode. In sourcing mode, the Profile Fetching Agent dispatches queries to all three platforms simultaneously using async parallel I/O. In resume mode, the Resume Parser Agent reads each uploaded file and extracts structured profiles.

Sourcing Mode: Parallel Fetch
Async dispatch to Google CSE, Naukri, and PDL simultaneously. Per-source error isolation — one source failing doesn't block others. Returns combined RawProfile[] with source attribution.
Resume Mode: ResumeParserAgent
The ResumeParserAgent reads each PDF/text resume via LLM extraction and produces structured RawProfile objects — name, title, skills, experience, education, and contact info. Handles wildly different formats. Falls back to heuristic parsing if LLM fails.
Emits RawProfile[] name, title, company skills[] experience[] source

Layer 05

Deduplication Layer

SourcingResume

The same person often appears across platforms (or duplicate resume uploads). This layer collapses them into a single canonical record using priority-ordered identity matching. Retains the best data per field and preserves alternate source URLs.

Scoring
Layer 06

Scoring & Ranking Layer

SourcingResume

The Ranking Agent scores each deduplicated profile against the SearchSpec using a transparent weighted formula. Must-have gate: missing more than 1 must-have skill = auto-rejected regardless of total score. Each profile gets a natural-language reasoning explanation.

Score Formula
Must-Have Skillsw1 = 50%
Nice-to-Have Skillsw2 = 25%
Seniority Levelw3 = 15%
Location Matchw4 = 10%
score = w1*must_have + w2*nice_have + w3*seniority + w4*location
Weights are recruiter-configurable, normalized to sum = 1.0

Layer 07

Output Layer

SourcingResume

Scored profiles are bucketed and delivered as structured JSON (for API/ATS integration) alongside a full execution trace. The trace records every tool call with input/output keys, total LLM invocation count, each HITL decision with recruiter overrides, and every refinement reason across iterations.

Server Interface
API Endpoints
Seven REST endpoints powered by FastAPI. Mutation endpoints support optional API key auth, per-IP rate limiting, and CORS. Streaming endpoints use Server-Sent Events with backpressure-controlled queues.
Method Endpoint Response Description
GET / — Serve frontend UI (static/index.html)
GET /api/config JSON Return model + source configuration (keys redacted)
POST /api/run JSON Run sourcing pipeline, return PipelineOutput
POST /api/run/stream SSE Run sourcing pipeline with real-time event streaming
POST /api/run/{run_id}/resume JSON Resume a HITL checkpoint (jd_review or profile_count)
POST /api/resume/match JSON Match uploaded resumes against JD
POST /api/resume/match/stream SSE Resume matching with real-time event streaming
